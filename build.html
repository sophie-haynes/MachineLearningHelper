Build models

In the last stage, we fixed the problems in our table. In this stage, we train models on it. First, we hold back part of the table, so that every model can be checked on rows it has never seen. Then we train models from three families, which differ in how they turn a row into a guess: distance-based, probabilistic and tree-based. The ensembles are built from trees, so they belong to the tree-based family. Finally, we put their scores side by side. The code on this page starts from the table you finished in the Prepare stage.

A model that is checked on the same rows it learned from can score well by memorising them. So before we train anything, we hold some rows back, and we work out the score a model would get without learning anything at all.

The columns the model learns from are called X, and the answer it is learning to guess is called y. drop gives us every column except the target, and the square brackets pick out the target on its own:

A distance-based model treats every row as a point, and guesses from the points that sit closest to it. Because it measures distance, the column with the biggest numbers would decide which rows count as close. So every model in this family has MinMaxScaler in front of it.







k-NN is short for "k nearest neighbours". For each new row, it finds the rows in the training set that sit closest to it, and guesses the answer that most of those neighbours have. n_neighbors=3 asks the three closest rows.

An SVM (support vector machine) draws a boundary between the rows of each answer, and places it so that the gap to the closest rows on either side is as wide as possible. A new row is guessed by the side of the boundary it falls on.


It measures distances too, so it uses the same scaling step. The code is the same as for k-NN, with SVC (the scikit-learn name for an SVM) in place of KNeighborsClassifier:

A probabilistic model works out a chance for each answer, and guesses the answer with the highest chance. The two models in this family get to that chance in different ways, and only one of them needs the columns on the same scale.







For each answer, Naive Bayes asks how common each of the row's values is among the training rows with that answer, and multiplies those shares together. It is called "naive" because it treats every column as if it had nothing to do with the others. GaussianNB is the version that works with number columns.


It looks at one column at a time, so a column with big numbers cannot drown out the others, and it needs no scaling step:




Example output
0.8257338768287673 0.826673547626069


On Bank Marketing, Naive Bayes scores 0.826 on the training set and 0.827 on the test set, which is below the score to beat (0.883). Do not throw a model away for this alone! The score only counts how many guesses were right, not which ones, and the Evaluate stage shows how to see which mistakes a model makes.


When you leave scaling out for a model, say why in your report.









Logistic regression learns one weight for each column. For a new row, it multiplies each value by its column's weight, adds the results together, and turns the total into a chance between 0 and 1.


It finds its weights more easily when the columns are on the same scale, so it goes in a pipeline with the scaler, like the distance-based models:




Example output
0.8928808417859513 0.892288410498378


On Bank Marketing, logistic regression scores 0.893 on the training set and 0.892 on the test set, a little above the score to beat (0.883).


If you see a warning that it "failed to converge", add max_iter=1000 inside LogisticRegression(), which gives it more steps to find its weights. On Bank Marketing, this warning appears when the scaler is left out, so check that your model is inside the pipeline first.










A tree-based model asks a series of yes/no questions about a row, such as "is visits 2 or fewer?". Each answer leads to the next question, until the row reaches a guess. Every question looks at one column on its own, so a tree needs no scaling.







A decision tree picks the question that best separates the answers in the training set, then picks another question for each side, and keeps going. random_state=0 makes it settle ties between questions the same way every time, so that your scores do not change between runs.




Example output
1.0 0.8347095252138013


On Bank Marketing, the tree scores 1.0 on the training set and 0.835 on the test set, which is worse than always guessing "no" (0.883). With no limit, a tree keeps asking questions until it has every training row right. It has memorised the training set, and what it memorised does not carry over to rows it has not seen.


To see how far it went, ask the tree how many questions deep it is:




Example output
47


A perfect training score next to a much lower test score is the sign to look for in your own tree. The next question shows the fix.









A tree that can only ask a few questions has to spend them on the patterns that hold for many rows, so it cannot memorise single rows. max_depth=5 stops the tree after five questions. We give this tree its own name, so that both trees can be compared later:

An ensemble combines many small models into one. The three ensembles on this page are all built from decision trees, so none of them needs scaling. They differ in how the trees are grown, and in how their guesses are combined.







A random forest grows 100 trees. Each tree is given a different random sample of the training rows, so the trees learn slightly different questions and make different mistakes. For a new row, every tree makes a guess, and the forest goes with the answer that gets the most votes. random_state=0 makes the random samples the same every time.




Example output
0.9998104085695326 0.8935417281038042


On Bank Marketing, the forest scores almost 1.0 on the training set, like the single tree with no limit, because each of its trees has no limit either. Its test score is 0.894 where the single tree scored 0.835: one tree's mistakes are outvoted by the others. Write down both numbers, and compare the test score with your score to beat.









A random forest grows its trees separately and lets them vote. Gradient boosting grows them in a row: the first small tree makes its guesses, the second tree is trained on what the first still gets wrong, and so on for 100 trees. The final guess adds all of the trees together.




Example output
0.898821373273928 0.893320554408729


On Bank Marketing, gradient boosting scores 0.899 on the training set and 0.893 on the test set. Its trees are small, so the two scores sit close together.


On a big table this can take a few minutes. If it does, write down how long it took, so that you can give it as a reason in your report.

Models in the same family get to their guesses in a similar way, so they often get the same rows wrong, and comparing them tells you little. Models from different families work in different ways, so comparing them tells you more. To choose, pick one model from each group below:
